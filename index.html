Each project starts with a concrete failure mode or workflow problem. The interesting part is not the model call. It is the retrieval, state, interfaces, trade-offs and behaviour around it.

01 / retrieval infrastructure

Tana Semantic Engine

A cloud-hosted intelligence layer for a live Tana workspace. It combines dense vector retrieval with lexical search and graph structure so AI clients can find information by meaning without losing the relationships that make it useful.

Problem

Keyword search misses meaning. Pure vector search flattens structure.

System

Hybrid retrieval, structural expansion, temporal provenance and reranking.

Delivery

Cloudflare edge deployment with OpenAPI, MCP and REST interfaces.

What I add

I’m useful where “just add AI” stops being a plan.

01

Turn fuzzy ideas into systems

I can take an ambiguous AI workflow, identify the actual information flow and failure modes, then build a prototype that makes the design concrete.

02

Connect models to real context

I work comfortably with APIs, MCP, semantic retrieval, structured data and the glue that lets an AI client interact with tools rather than live in a chat box.

03

Think about reliability early

My physics background makes me care about signals, calibration, evidence and measurement. I naturally ask what a system can infer, what it cannot, and how we know.

04

Explain the technical work

I like making architecture and trade-offs legible. A recruiter, client or collaborator should be able to see what the system does without reading the entire codebase first.
